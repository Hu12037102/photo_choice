# Live Photo 静态导出列表状态设计

**日期：** 2026-07-06
**状态：** 已确认
**范围：** 开启图片压缩时，Live Photo 的预览导出偏好、相册列表角标与最终结果交付

## 1. 背景

开启压缩后，用户可以在预览页为每个 Live Photo 选择“保留 Live”或“导出静态”。当前导出策略已经按媒体 ID 保存在 `LivePhotoExportPolicy` 中，完成选择时也会读取该策略；但相册列表的 Live 图标只表达源素材属性，不表达当前导出偏好。

因此，用户在预览页选择“静态”并返回列表后，列表仍显示普通 Live 图标，视觉状态与最终产物不一致。另外，当前压缩失败会回退原始 URI；对选择“静态”的 Live Photo 而言，这可能实际回传 Live 原图，与用户选择冲突。

## 2. 目标

- 相册列表准确表达 Live Photo 当前会以 Live 还是静态图片导出。
- 列表、预览和最终结果交付读取同一导出状态源。
- 导出偏好不依赖选中状态；未勾选或取消勾选后仍保留。
- 用户选择“静态”后，结果必须是静态 JPEG；失败时不得静默回退 Live 原图。
- 保持普通图片、GIF、视频和“保留 Live”的现有行为不变。

## 3. 非目标

- 不将导出偏好持久化到下一次选择器会话。
- 不改变 Live Photo 的检测、索引或播放方式。
- 不重新设计预览页的“Live / 静态”切换控件。
- 不改变普通静态图片压缩失败时的现有回退策略。

## 4. 业务行为

### 4.1 默认状态

- Live Photo 默认选择“保留 Live”。
- 列表显示现有 Live 图标。
- 完成时返回原始媒体 URI，不进行图片压缩，保留动态内容。

### 4.2 静态导出状态

- 用户在预览页切换为“静态”后，列表中对应媒体项显示“Live 图标 + 斜杠”。
- 状态以媒体 ID 为单位，在本次选择器会话内保留。
- 媒体是否已勾选不影响导出偏好。取消勾选、返回列表或再次进入预览后，仍显示并使用之前的偏好。
- 用户切回“Live”后，列表恢复普通 Live 图标。
- 关闭压缩时不存在静态导出偏好，列表始终使用普通 Live 图标。

### 4.3 会话边界

- 导出偏好仅存于当前 `PhotoChoiceViewModel` 会话。
- 选择器结束并重新打开后，所有 Live Photo 恢复默认“保留 Live”。
- 不写入磁盘、MediaStore 或 Live Photo 检测索引。

## 5. 视觉规范

### 5.1 选定方案

采用方案 A：在现有 16dp 白色 Live 图标上叠加白色对角斜杠。

- Live 图标保持 100% 不透明度。
- 不对图标整体降透明度，避免在复杂或高亮缩略图上降低辨识度，也避免形成“控件不可用”的误解。
- 斜杠与现有图标使用相同白色，端点为圆角，视觉重量与现有圆环和放射线协调。
- 图标继续位于缩略图左下角，沿用现有 6dp 边距和 16dp 尺寸。
- 不增加文字、胶囊背景或额外颜色。

新增独立矢量资源 `ic_live_photo_off.xml`。它复用现有 Live 图标路径并在同一 24 × 24 viewport 内增加从左下到右上的斜杠，避免运行时叠加 View 或 Canvas 绘制带来的对齐差异。

### 5.2 无障碍

- 普通状态的内容描述保持“Live Photo”。
- 静态导出状态使用“Live Photo，静态导出”。
- 状态变化后同步更新内容描述。

## 6. 状态模型

`LivePhotoExportPolicy` 是导出偏好的唯一状态源。它应暴露不可变的“静态导出媒体 ID 集合”，默认集合为空：

- ID 不在集合中：保留 Live。
- ID 在集合中：导出静态。
- 切换回 Live：从集合移除 ID。

状态对外通过 `StateFlow<Set<Long>>` 提供。每次实际变化发布新集合；重复设置相同状态不发布更新。

保留 `isKeepLive(mediaId)` 作为预览和导出层的查询入口，避免调用方理解内部集合语义。选中状态由 `SelectionManager` 独立管理，任何选择或取消选择操作都不得清理导出偏好。

## 7. 列表数据流

`MediaGridFragment` 监听静态导出 ID 集合，并计算前后集合的对称差，只通知发生变化的媒体 ID。`MediaGridAdapter` 增加专用的导出状态 payload，不触发缩略图重载或整个分页列表刷新。

Adapter 在完整绑定、Live 检测 payload 和导出状态 payload 中，都通过同一个状态解析逻辑决定图标：

1. 媒体必须已判定为 Live Photo。
2. 压缩必须已开启。
3. 媒体 ID 必须处于静态导出集合。
4. 三个条件同时满足时显示带斜杠图标；否则 Live Photo 显示普通图标。

Live Photo 检测可能异步完成。检测完成后的 payload 必须重新读取当前导出偏好，确保不会用普通 Live 图标覆盖已选择的静态状态。反过来，导出偏好变化时也必须重新读取当前检测结果；未知或已确认非 Live 的媒体不显示角标。

## 8. 预览数据流

预览页继续通过 `LivePhotoExportPolicy` 读取和切换当前媒体的导出偏好：

- 初次进入时默认显示“保留 Live”。
- 切换后立即更新预览控件和共享状态流。
- 再次进入同一媒体时从共享状态恢复“Live”或“静态”。

列表和预览不得各自维护一份 UI 缓存状态。

## 9. 导出与失败处理

`PhotoChoiceActivity` 构建导出任务时，为“Live Photo + 选择静态”的条目标记 `mustExportStatic = true`。该标记与普通的 `shouldCompress` 分开表达：前者是结果格式约束，后者是处理动作。

### 9.1 成功

- Live Photo 选择静态并压缩成功：返回沙盒中的静态 JPEG `file://` URI 和绝对路径。
- Live Photo 保留 Live：返回原始 `content://` URI。
- 其他媒体沿用现有策略。

### 9.2 强制静态项失败

如果任一 `mustExportStatic` 条目未生成有效 JPEG：

- 停止整个结果交付，不调用宿主结果回调，也不设置成功 Activity Result。
- 不回退该条目的原始 Live URI。
- 删除本轮导出已生成但尚未交付的临时文件，避免留下无用的部分结果。
- 清除“交付进行中”状态，使用户可以重试。
- 保留当前选择和所有导出偏好。
- 在选择器页面显示明确提示：“静态图片导出失败，请重试”。

预览页点击完成后会先关闭并回到相册页，再由相册 Activity 执行导出。因此失败提示显示在相册页，用户可以再次进入预览切换策略或直接重试完成。

### 9.3 非强制静态项失败

普通静态图片压缩失败时继续回退原始静态 URI，以保持现有业务行为。该回退不会改变媒体的静态属性，因此不违反本设计的结果语义。

## 10. 性能

- 状态变化只刷新对应媒体 ID，不调用 `notifyDataSetChanged()`，不重新提交 PagingData。
- 导出状态 payload 只更新角标资源、可见性和内容描述，不重新发起 Glide 请求。
- 静态导出 ID 集合通常仅包含少量用户主动切换的条目，复制不可变集合的成本可忽略。
- Live Photo 检测和索引流程不增加新的磁盘或 MediaStore 查询。

## 11. 测试与验收

### 11.1 单元测试

- `LivePhotoExportPolicy` 默认保留 Live。
- 切换静态后 ID 进入集合，切回 Live 后移除。
- 重复设置相同状态不产生额外状态变化。
- 选中或取消选中媒体不改变导出偏好。
- 图标状态解析覆盖压缩开关、Live 检测结果和导出偏好的全部组合。
- Live 静态项压缩成功时返回 JPEG。
- Live 静态项压缩失败时不回传原 URI，并将交付判定为失败。
- 多选中任一强制静态项失败时，整批不交付。
- 普通静态图片压缩失败仍按现有策略回退原 URI。

### 11.2 回归验证

- 普通图片、GIF、视频的角标与导出行为不变。
- “保留 Live”继续回传原始 URI。
- 单选与多选模式均可正常完成。
- Contract 与 callback 两条结果轨道行为一致。

### 11.3 手工 UI 验收

- 在预览切换静态后返回列表，对应 item 立即显示带斜杠图标。
- 未勾选、取消勾选、滚动出屏并复用 ViewHolder 后，状态仍正确。
- Live Photo 异步检测完成后直接显示与当前导出偏好一致的图标。
- 再次进入预览时控件状态与列表一致。
- 浅色和深色主题下，在亮色、暗色和高细节缩略图上均清晰可辨。
- 斜杠不超出 16dp 图标边界，不遮挡右上角选择控件或视频时长区域。

## 12. 验收结论

本设计完成后，Live Photo 的源素材属性、用户选择的导出偏好和最终结果格式形成闭环：普通 Live 图标表示保留动态，带斜杠图标表示本次会话将严格导出静态 JPEG；任何无法满足该承诺的失败都不会静默交付 Live 原图。
